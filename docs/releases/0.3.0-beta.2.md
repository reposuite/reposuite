## Why `0.3.0-beta.2` is required before WORK Phase C (Pairing)

During WORK handoff preparation and live read-only WSS probing against
`wss://app.reposuite.com/gateway` (deployed from `reposuite-gw`
`feature/gateway-naming@4a828d2d73508fc98fb75f1e052fce17523ea7c0`), Lead
identified and verified a wire-field mismatch in `0.3.0-beta.1`:

- `rceman/reposuite-gateway@deec606` serialized `GatewayHello.GatewayKey`
  and `GatewayHelloResult.GatewayKey` as `json:"gateway_key,omitempty"`.
- Deployed RepoSuite Control (`4a828d2`) expects and emits
  `json:"gateway,omitempty"`.
- Live non-destructive WSS probe against `wss://app.reposuite.com/gateway`:
  - `{"gateway":"gw_0000000000000000","credential":"probe","epoch":1,"agent_version":"probe"}`
    → `{"ok":false,"epoch":0,"error":"gateway_unknown"}` (reaches `resume`)
  - `{"gateway_key":"gw_0000000000000000","credential":"probe","epoch":1,"agent_version":"probe"}`
    → `{"ok":false,"epoch":0,"error":"invalid_hello"}` (rejected at field parse)

`0.3.0-beta.2` fixes `internal/cloud/rpc.go` in `rceman/reposuite-gateway`
to use `json:"gateway,omitempty"` and adds raw-wire regression test
`TestCanonicalWireHandshakeClaimPersistResumeReconnect` covering first
invite claim, `0600` `gateway.json` persistence, authenticated resume,
and `epoch_mismatch` resync without live Owner invites.

## Distribution lifecycle corrections (approved, WORK R0-verified)

1. **HTTP Host header fix (R0-confirmed root cause of the WORK Phase B
   failure)**: `http_tcp()` sent `Host: 127.0.0.1` without the dynamic Relay
   port. Relay enforces strict Host validation (`127.0.0.1:<port>`, ADR-006)
   and returns HTTP 421, so `relay_probe` never succeeded — the ~30s health
   timeout, rollback, and partial install all followed. `http_tcp()` now
   sends `Host: 127.0.0.1:<port>`; `relay_probe()`, `health_wait()` and
   `running_sessions()` all go through it. The lifecycle test fixture now
   enforces the same strict Host rule (HTTP 421 on a portless Host).
2. **First-install rollback semantics**: `restore()` with no previous version
   restarted the units it had just deleted ("RECOVERY FAILED" + orphan
   daemons). It now stops/disables the new units while their files exist,
   removes files + `current`, and reaps orphans — end state "not installed".
3. **Partial-install orphan reap**: `owned_pids()` scans `/proc/*/exe` for
   executables under `versions/`/`current/bin` matching owned binary names
   and skips any process whose systemd unit is still active (managed services
   are never terminated); `apply_runtime` reaps survivors of a previous
   partial install before `restart`, with a bounded SIGTERM→SIGKILL window
   and fail-closed verification.
4. **Health diagnostics**: `health_wait` reports the timed-out leg
   (`gateway socket` / `relay api.token` / `relay listenPort` /
   `relay /v1/daemon probe`) so a future failure is self-describing.

Regression evidence: `scripts/test-lifecycle.js` 21/21 (new cases:
first-install health failure → clean removal, delayed readiness, strict-Host
fixture, partial-install orphan reap).
